POLICY ENFORCEMENT

Security Gate

The Python backend decides whether an action label is allowed. Unknown and dangerous labels are rejected by the configured policy.

safe_demo, validate_config, check_agent_status, verify_audit_chain, generate_test_report.

🔴

Blocked labels

Destructive, unauthorized, data theft, security bypass, credential theft and related labels.

🔒

Quarantine

The current backend blocks actions while the agent is in jail.

🧠

Learned rules

Previously recorded safety rules can cause an action to be avoided.

Rules: —

How the gate evaluates a proposal

  1. Receive one action label from the local test or AI proposal.
  2. Compare the label with the configured allow-list.
  3. Allow only the five safe demonstration labels.
  4. Reject blocked or unknown labels and record the result.
  5. Refresh the agent state and audit history.

Quarantine lifecycle

A blocked test can switch the agent into a quarantined state. The monitor changes to red alert mode, and further actions remain subject to the backend's existing rules. Releasing the agent changes its state; it does not erase audit history or learned rules.

Important: this dashboard simulates decisions using action labels. It does not execute file deletion, credential theft, network scanning, or other real operations.

Policy boundary

Safe labels are explicitly listed. Dangerous labels are deliberately included as negative test cases to verify that the gate rejects them. Unknown labels should not be treated as safe.

Audit and observability

The backend status response supplies the current quarantine state, learned-rule count, and recent event records. Use Audit Explorer to inspect the records returned by the server.

PROJECT DOCUMENTATION / 001

AI Virtual Jail — Test Tower

An experimental AI safety sandbox designed to demonstrate how action proposals can be checked, rejected, contained, and recorded before any real-world operation is considered.

BUILT BY Entity_Yubraj × ChatGPT
🧭

Project objective

Explore a transparent control layer around AI-generated action labels. The goal is to make safe and blocked decisions visible, understandable, and reviewable.

⚙️

How it works

The browser sends a test request to the Python backend. For autonomous tests, a cloud model may suggest one label. The backend applies its configured policy and returns a decision for the monitor and audit view.

🛡️

Security Gate

The gate allows five safe demonstration labels and rejects the blocked test labels. The browser displays the result; the backend remains responsible for the decision.

🚨

Quarantine & release

A blocked attempt can place the agent in quarantine. The interface highlights that state in red. Release returns the agent to an active state according to the backend endpoint.

📜

Audit Explorer

Recent event records help inspect test outcomes and understand what happened during a session. Audit visibility supports debugging and learning.

☁️

Optional cloud AI

The autonomous proposal flow can use a configured API provider. Manual safe tests run locally. API keys must remain on the backend or in secure local configuration, never in this HTML page.

🧱

Technology architecture

Frontend: HTML, CSS and JavaScript. Backend: Python HTTP API. The interface communicates through the existing status, action, auto, autonomous, and release endpoints.

⚠️

Scope & limitations

This is an educational simulation, not a hardened sandbox, penetration-testing platform, or proof of AI safety. The 17 action names are labels only; they do not perform the named destructive operations.
